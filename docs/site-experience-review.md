# Публичный сайт и кабинет администратора

Проблема: вход администратора был незаметен, кабинет показывал фиктивные показатели, часть редакторов не сохраняла изменения, публичные страницы использовали жёстко заданные блоки. Теперь вход доступен в шапке, подвале и мобильном меню, а контент сайта и кабинета берётся из одной базы Supabase.

## Изменения

- Кабинет: реальная статистика, CRUD меню/событий/галереи/отзывов, публикация и модерация, список последних 200 бронирований и изменение статуса.
- Навигация: переход на сайт без выхода, отдельное завершение сессии через серверный POST, ссылка назад со страницы входа.
- Главная, меню, афиша и раздел «О нас»: реальные записи, пустые состояния и сообщение при ошибке загрузки. Удалённые записи не появляются снова из fallback.
- Семь тематических стоковых фотографий, оптимизация Next/Image, галерея с просмотром и клавиатурной навигацией. Копии загружены в Supabase Storage; источники и лицензия — в `public/images/stock/CREDITS.md`.
- Демо-контент в настроенном Supabase: восемь блюд/напитков, четыре события, семь фотографий, четыре вымышленных отзыва и две демо-брони. События и отзывы явно обозначены; один отзыв оставлен на модерации для проверки.
- Телефон владельца +996 779 118 824, ежедневно 10:00–22:00, Asia/Bishkek. Адрес «Бишкек, ул. Литературная, 12» вымышленный и подписан как демо-адрес.

## Проверка

`npm test`: 95 тестов; `npm run lint` и production build проходят. Покрыты строгий status-only PATCH бронирования, запрет доступа постороннему пользователю, отсутствующий/недоступный контент и same-origin logout. Мобильный Lighthouse для локальной production-сборки с живым Supabase: performance 97, accessibility 100. Это измерение облачной среды, не обещание идентичного результата Vercel.

Браузерная интеграция выполняется на production-сборке против настроенного Supabase: создание, изменение и удаление контента; публикация события; скрытие отзыва на модерации, публикация и удаление без повторного появления; подтверждение брони; мобильная навигация. Для проверок используются временные пользователи и записи, удаляемые после проверки. Реальная учётная запись владельца не изменяется.

## Развёртывание и границы

Новая SQL-миграция и дополнительные env не требуются. Демо-данные и изображения уже добавлены в настроенный Supabase. Seed не запускается автоматически, сохраняет существующие изменения и может восстановить удалённые демо-записи только при явном повторном запуске.

Event RSVP с вместимостью остаётся отложенным. UI загрузки файлов остаётся этапом Book of the Month; галерея пока редактируется по HTTPS-ссылке. Команды Telegram описаны в `docs/telegram-bot-plan.md`, обработчик команд и webhook в эту доработку не входят.
