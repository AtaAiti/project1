# Telegram MVP — проверка первого релиза

Реализованы этапы 1–2 из `telegram-bot-plan.md`: webhook, RU/EN, публичные ссылки/афиша, приватные команды броней, кнопки подтверждения и двухшагового отклонения, одноразовая привязка сотрудников в веб-кабинете. Первоначальная привязка владельца и регистрация webhook — через setup-скрипт.

## Выполненные проверки

- Vitest: 218 тестов; строгая схема update, Unicode/лимиты Telegram, адресованные команды, запрет групповых приватных команд и неподключённых пользователей, просроченные ссылки, проверка прав при доставке, retry, webhook secret/ротация/ограничение тела, API статусов.
- PGlite: миграция применяется повторно, решение + audit + dedup + outbox атомарны, неверная задача откатывает транзакцию, одноразовая привязка, lease/ack, запрет браузерным ролям.
- Реальный Supabase: параллельные confirm/decline дают ровно один changed и один conflict; повторный update не создаёт второго решения; ровно одна audit-запись; anon не может читать настройки или выполнять status RPC; использованный link token недействителен. Временные строки удалены.
- Браузер, мобильный размер 390×844, production build локально + реальный Supabase: сотрудник получает одноразовую ссылку из кабинета; подписанный webhook привязывает личный чат; `/confirm` меняет общую бронь; удаление сотрудника даёт API 403 и подавляет уже поставленный в очередь приватный ответ; повторный update не меняет audit. Anonymous link API — 401. Исходящие сообщения в этом тесте отключены. Временные Auth-пользователь, настройки бота, заявки и очередь удалены.
- ESLint, TypeScript и Next.js production build проходят.

## Границы

Схема столов по-прежнему демонстрационная; бот подтверждает заявку, а не атомарно выделяет table_id/интервал. RSVP команды администрирования и уведомления гостям требуют следующих этапов. Первоначальная отправка уведомления сайта остаётся best effort; outbox этого релиза защищает ответы на Telegram updates. Старые карточки обновляются при действии, а не фоновым редактированием после каждого веб-изменения. Сетевая неоднозначность может повторить ответ Telegram, но не решение брони.
