# Telegram-бот «ЛитераторЪ»: предлагаемый сценарий

Сейчас @Literator1Bot работает как канал уведомлений владельцу: заявка сохраняется в Supabase, затем приходит сообщение в настроенный приватный chat_id. Команды, webhook и inline-кнопки пока не реализованы. Эта доработка сайта не объявляет их работающими.

## Посетитель

| Команда | Ответ |
| --- | --- |
| `/start` | Приветствие и кнопки «Сайт», «Меню», «Забронировать стол», «Контакты» |
| `/help` | Краткая инструкция и пояснение: бронь подтверждается администратором |
| `/site` | Ссылка на публичный сайт с выбором RU/EN |
| `/menu` | Ссылка на актуальное меню сайта |
| `/contacts` | Телефон, часы 10:00–22:00, WhatsApp; адрес явно помечен как демонстрационный |

Первый этап — ссылки на существующие формы, без второй независимой системы бронирования внутри бота. Персональные данные, заявки и статистика посетителям не выдаются. Пока не появится обработчик webhook, `/start` только позволяет боту отправлять сообщения этому пользователю.

## Владелец в приватном чате

| Команда | Ответ |
| --- | --- |
| `/today` | Брони на сегодня по Asia/Bishkek, сгруппированные по статусу |
| `/pending` | Последние ожидающие заявки; при большом списке — пагинация |
| `/booking <id>` | Карточка одной заявки с именем, телефоном, временем, гостями и комментарием |
| `/confirm <id>` | Перевод заявки в confirmed |
| `/decline <id>` | Перевод заявки в declined с возможностью ввести причину |
| `/events` | Ближайшие опубликованные события, без фиктивных RSVP-счётчиков |
| `/stats` | Реальные показатели: меню, опубликованные отзывы, события и ожидающие заявки |
| `/admin` | Ссылка на защищённый веб-кабинет |

Сообщение о новой брони: короткий ID, имя, нормализованный телефон, дата/время Asia/Bishkek, количество гостей и комментарий. Inline-кнопки «Подтвердить», «Отклонить», «Открыть кабинет» удобнее длинных команд. Команды остаются запасным способом управления.

## Ограничения и защита будущей реализации

- Доступ к приватным командам — по неизменяемому Telegram user_id и разрешённому private chat_id, не по username. Username может измениться.
- Webhook проверяет `X-Telegram-Bot-Api-Secret-Token`; секрет хранится отдельно как `TELEGRAM_WEBHOOK_SECRET`.
- Повторный `update_id` и callback обрабатываются идемпотентно; устаревшее подтверждение показывает текущий статус.
- Обновление статуса идёт через общий серверный слой, используемый также веб-кабинетом. Никаких SQL или service-role ключей в сообщениях.
- Уведомление о результате получает владелец. Посетителю нельзя отправить Telegram-подтверждение только по телефону: для этого нужен отдельный opt-in и связанный Telegram chat_id; в текущей форме такой связи нет.
- Публичные команды ограничиваются по частоте, не отражают сырые сообщения ботов и не сохраняют лишние данные.
- RSVP с вместимостью и управление RSVP в Telegram добавляются после отдельного согласования PR 2/PR 3.

Рекомендация: следующим Telegram-этапом сделать webhook, проверку owner user_id, `/pending`, `/today` и inline confirm/decline. Оставить создание заявки в единственной веб-форме. Эти команды — проект сценария, а не реализованные возможности текущего PR.
