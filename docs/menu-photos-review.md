# Фото блюд и напитков

Раньше в редакторе меню не было поля фото, а публичные карточки выбирали общую картинку по категории, даже если требовалось отдельное фото позиции.

Теперь `/admin/menu` позволяет загрузить или заменить JPEG/PNG/WebP, до 4 МиБ. Изображение загружается через защищённый `/api/admin/media` в public bucket `media`, папка `menu`, с уникальным UUID. Ссылка сохраняется в `menu_items.image_url` после нажатия «Сохранить». Пока загрузка идёт, сохранение и закрытие редактора заблокированы. Фото обязательно для создания позиции; допустима ссылка HTTPS. Приватные ключи остаются на сервере.

Карточки меню RU/EN и превью на главной используют фото конкретной позиции. Для старых записей миграция устанавливает иллюстрации категорий; их интерфейс явно подписывает. Недоступная ссылка автоматически заменяется иллюстрацией соответствующей категории. Пользовательские фото при повторном применении SQL сохраняются.

SQL: `supabase/migrations/20261022000100_0005_menu_photos.sql`, применена владельцем к Supabase. Новых env или пакетов нет. RLS и запрет загрузки неадминистратором сохранены. Ограничение 4 МиБ учитывает лимит тела запроса функции Vercel вместе с multipart overhead.

После замены фотографии прежний объект Storage автоматически не удаляется: он может использоваться другой записью. Неиспользованные загрузки после отмены также требуют отдельной очистки. Удалять файлы вручную следует только после проверки всех ссылок на них.

План Telegram-бота для передачи разработчику обновлён отдельно в `docs/telegram-bot-plan.md`: текущий RSVP уже учитывается, подтверждение брони отделено от регистрации на событие, а создание webhook не выполнялось в этой задаче.

## Проверки

- SQL проверен на изолированном PostgreSQL: backfill, повторное применение без потери фото, ограничения путей и сохранение RLS.
- Проверены обязательное фото, безопасные URL, папка menu, тип/размер файла, авторизация upload API и ошибки Storage.
- Браузер с настоящим Supabase: временный администратор загрузил JPEG, создал позицию, увидел загруженное изображение в RU/EN меню и на главной, заменил его без устаревшего кэша. Неверный формат и повреждённая ссылка проверены, обычный пользователь получает 403, анонимный — 401. Временные записи, объекты Storage и Auth-пользователи удалены.
- Мобильная версия 390px проверена без горизонтального скролла. Сборка и lint проходят.
- Финальная проверка: 188 тестов проходят. Дополнительно браузером проверены запрет сохранения во время загрузки и отклонение файла больше 4 МиБ до обращения к Storage; прежнее фото при ошибке сохраняется.
