# ЛитераторЪ

Двуязычный сайт бара и клуба любителей чтения: **«Место встречи между строк»**. Рабочая версия: https://literator-xi.vercel.app/ru.

Исходный план — [Project 1.docx](<Project 1.docx>). Состояние приёмки, результаты проверок и ограничения среды: [docs/project1-final-review.md](docs/project1-final-review.md). Сценарий презентации: [docs/project1-demo.md](docs/project1-demo.md).

Заведение демонстрационное: адрес «Бишкек, ул. Литературная, 12» вымышленный и подписан на сайте. Часы — ежедневно 10:00–22:00, часовой пояс — **Asia/Bishkek**. Стоковые изображения имеют подписи; источники — [public/images/stock/CREDITS.md](public/images/stock/CREDITS.md).

## Стек и структура

Next.js 16 App Router / React 19, TypeScript, Tailwind CSS 4; Supabase PostgreSQL, Auth и Storage; Zod; Telegram Bot API; Vercel. Проверки: Vitest, PGlite, Playwright, axe-core, Lighthouse.

```text
src/app/[locale]/        Главная, о нас, меню, афиша, контакты, столы; RU/EN
src/app/booking/         «Литературный резерв», локаль через ?locale=ru|en
src/app/admin/           Вход, восстановление пароля, защищённый кабинет
src/app/api/             Брони, RSVP, отзывы, административные API, Telegram webhook
src/components/          Публичный интерфейс, формы и редакторы кабинета
src/lib/                 Валидация, переводы, SEO, серверные сервисы и Supabase
src/proxy.ts             Язык документа и дополнительная защита /admin
src/data/                Демонстрационный контент
src/app/sitemap.ts       Публичные страницы и опубликованные события
src/app/robots.ts        Правила индексации
dictionaries/           ru.json и en.json
supabase/migrations/     Версионированные изменения базы
scripts/                 Демо-данные, настройка бота и проверки приёмки
tests/                   Unit/API-тесты и PostgreSQL-тесты миграций
docs/                    Проверки, эксплуатация и презентация
```

Основные страницы: `/{locale}`, `/about`, `/menu`, `/afisha`, `/contacts` под префиксом `/ru` или `/en`. Смена языка сохраняет текущую страницу, в том числе конкретное событие. `/` перенаправляет на `/ru`. Справочный `/{locale}/styleguide` исключён из индексации.

## Локальный запуск

Нужны **Node.js 24 LTS** и npm. Для обычного запуска Docker не требуется.

```bash
npm ci
cp .env.example .env.local
# Заполните .env.local своими значениями.
npm run dev
```

Откройте http://localhost:3000/ru. Без Supabase публичные страницы показывают явно обозначенный локальный демо-набор. Отправка брони без серверной конфигурации запрещена; приложение не имитирует сохранение реальной заявки.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | URL проекта Supabase |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Публичный ключ для Auth и чтения разрешённого контента |
| `SUPABASE_SERVICE_ROLE_KEY` | Только сервер: сохранение заявок, rate limit, административные операции |
| `ADMIN_USER_ID` | UUID владельца; основная проверка личности и управление сотрудниками |
| `ADMIN_EMAIL` | Email владельца без учёта регистра; резервная проверка, когда UUID пуст |
| `ADMIN_USER_IDS` | Необязательные дополнительные UUID через запятую или `;` |
| `ADMIN_EMAILS` | Необязательные дополнительные email; обычно сотрудников добавляют через кабинет |
| `TELEGRAM_BOT_TOKEN` | Только сервер: команды и уведомления Telegram |
| `TELEGRAM_CHAT_ID` | Личный chat_id владельца для уведомлений и первоначальной привязки бота |
| `VERCEL_PROJECT_PRODUCTION_URL` | Vercel задаёт автоматически. Production-домен для canonical, sitemap и ссылок; локально используется `literator-xi.vercel.app` |

Настоящие значения не коммитятся. `.env.example` содержит placeholders. Для Codex с сетевым прокси запускайте сервер, сборку и сетевые скрипты с `NODE_USE_ENV_PROXY=1`; на обычном компьютере и Vercel это, как правило, не нужно. Серверные скрипты не загружают `.env.local` автоматически: передайте переменные через окружение или `node --env-file=.env.local ...`.

## Supabase и доступ

Для новой базы примените миграции из `supabase/migrations` по порядку:

1. `20261013000100_0001_baseline.sql` — исходные таблицы и публичное чтение.
2. `20261013000200_0002_foundation.sql` — ограничения, RPC rate limit, Storage.
3. `20261014000100_0003_event_rsvp.sql` — атомарная запись на события с вместимостью.
4. `20261015000100_0004_menu_and_team.sql` — размеры порций и закрытый список сотрудников.
5. `20261022000100_0005_menu_photos.sql` — фотографии позиций меню.
6. `20261022000200_0006_telegram_bot.sql` — привязки бота, очередь ответов, история решений.

В существующей базе выполняйте только ещё не применённые изменения. `supabase/schema.sql` — справочный снимок, а не замена миграциям.

Создайте владельца в Supabase Auth и задайте `ADMIN_USER_ID`. В Supabase → Authentication → URL Configuration настройте:

- Site URL: `https://literator-xi.vercel.app`.
- Redirect URL: `https://literator-xi.vercel.app/admin/reset-password`.
- Для разработки: `http://localhost:3000/admin/reset-password`.

Вход — `/admin/login`: email, пароль или «Задать или восстановить пароль». Письмо нужно открыть в том же браузере. Supabase управляет доставкой Auth-писем; для приглашений внешним пользователям проверьте настройки SMTP и ограничения почтового сервиса.

Семь последовательных нажатий на логотип открывают вход в кабинет; пауза более 1,2 секунды или нажатие вне логотипа сбрасывают счётчик. Эта навигация дополняет серверную авторизацию. Proxy, защищённый layout и каждый административный API независимо проверяют доступ. Без конфигурации владельца/администраторов доступ закрыт. Владелец управляет подтверждёнными аккаунтами сотрудников в `/admin/team`; сотрудник не получает право управлять командой.

## Контент и заявки

- Меню, события, галерея и отзывы читаются из Supabase. Удалённые записи не заменяются демо-данными; пустая живая таблица остаётся пустой. Ошибки загрузки имеют понятное сообщение и повтор.
- В `/admin/menu` фото позиции загружается через сервер в Storage: JPEG/PNG/WebP до **4 МБ**, с проверкой MIME и сигнатуры. У новой позиции фото обязательно. Галерея и изображения событий пока редактируются по HTTPS-ссылке.
- Bucket `media` публичен для чтения; запись разрешена только серверу после проверки администратора. Папки: `menu`, `gallery`, `books`; лимит bucket — 5 MiB, лимит серверной загрузки — 4 МБ.
- Отзывы посетителей поступают на модерацию; неопубликованные отзывы скрыты от публики.
- Бронь: имя, кыргызстанский телефон, будущие дата/время в пределах 10:00–22:00, гости, комментарий. Телефон нормализуется в `+996` и 9 цифр. Лимит — 5 запросов за 600 секунд; единственный backend — атомарная Supabase RPC, недоступная браузерным ролям. Истёкшие счётчики очищаются при записи.
- Honeypot возвращает имитацию успеха без записи и Telegram. Ошибки формы переводятся через общие ключи словарей.
- Успешная отправка означает сохранённую заявку `pending`; доступность подтверждает администратор. Сбой Telegram не превращает сохранение в ошибку. Подтверждение/отклонение выполняются атомарно с ожидаемым статусом и журналом автора; конфликт возвращает понятную ошибку.
- План восьми столов демонстрационный. Выбор стола сохраняется как пожелание в комментарии; это не учёт занятости по интервалам. Черновик формы хранится в памяти страницы, без записи персональных данных в localStorage.
- RSVP резервирует места через отдельную атомарную RPC. Повторная запись и превышение вместимости запрещены; отмена освобождает места. Нельзя переносить событие с участниками или уменьшать вместимость ниже занятого количества. Детали: [docs/pr2-review.md](docs/pr2-review.md).

Демо-наполнение запускается вручную скриптами в `scripts/`. Оно не выполняется при сборке и может восстановить ранее удалённые демо-записи. Не запускайте seed на базе с настоящим контентом без проверки списка UUID и назначения скрипта.

## SEO, приватность и доступность

Публичные страницы имеют локализованные title/description, Open Graph, Twitter Card, canonical и взаимные RU/EN/x-default ссылки. Время и ссылки событий согласованы с Asia/Bishkek. Sitemap читает только опубликованные события публичным ключом; ошибки живой базы не подменяются демонстрационными URL. Административные страницы и стайлгайд имеют `noindex` и исключены из sitemap; robots закрывает также API. Для защиты данных используется авторизация, а не robots.

`html lang` соответствует URL уже в серверном HTML и обновляется при переходах без перезагрузки. Окно 18+ локализовано и требует явного ответа. В модальных окнах удерживается фокус; меню и галерея закрываются по Escape. Есть переход к основному содержимому, видимый фокус и поддержка reduced motion. Фотографии выводятся через `next/image`, с адаптивными размерами и отложенной загрузкой вне первого экрана.

Cookie-баннер сохраняет выбор на устройстве. Внешняя карта OpenStreetMap загружается только после согласия; его можно отозвать в подвале. Необходимые Auth-cookie используются для кабинета. Аналитика и рекламные cookie не подключены. Карта показывает центр Бишкека, а не точку вымышленного заведения.

## Telegram

Рабочий бот: https://t.me/Literator1Bot. Посетителям доступны `/start`, `/help`, `/menu`, `/tables`, `/book`, `/events`, `/contacts`, `/language`. Подключённым администраторам — `/today`, `/pending`, `/booking <id>`, `/confirm <id>`, `/decline <id>`, `/admin`.

После миграций и деплоя:

```bash
node --env-file=.env.local scripts/setup-telegram-bot.mjs          # Только проверка
node --env-file=.env.local scripts/setup-telegram-bot.mjs --apply  # Подключение/ротация
```

Скрипт проверяет личный чат владельца, генерирует webhook secret в памяти и сохраняет только его SHA-256. Он не сбрасывает накопленные updates. Сотрудники подключаются одноразовой ссылкой из `/admin/telegram`; права веб-аккаунта проверяются на каждой приватной команде и перед доставкой отложенного ответа.

Решение по брони, dedup update и запись ответа в outbox — одна транзакция. Неоконченная доставка вызывает повтор webhook без повторного решения. Первоначальные уведомления сайта пока отправляются best effort. Эксплуатация и дальнейшие этапы: [docs/telegram-bot-plan.md](docs/telegram-bot-plan.md).

## Проверки

```bash
npm test
npm run lint
npm run build
npm run start
```

Vitest проверяет валидацию, API, словари, SEO, права и миграции PostgreSQL через PGlite. Для браузерной проверки установите браузеры и их системные зависимости:

```bash
npx playwright install --with-deps chromium firefox webkit
npx playwright install msedge
npm run qa:browsers -- http://localhost:3000
npm run qa:lighthouse -- http://localhost:3000
```

Можно указать production URL вместо localhost. `QA_BROWSERS=chrome,firefox` выбирает движки; `QA_REPORT_DIR` — папку отчётов. Исполняемые файлы можно задать через `QA_CHROME_EXECUTABLE`, `QA_EDGE_EXECUTABLE`, `QA_WEBKIT_EXECUTABLE`. `chrome` использует Chrome for Testing от Playwright, `webkit` проверяет движок Safari, но не заменяет испытание приложения Safari на устройстве Apple.

Флаг `--with-auth` у браузерного скрипта дополнительно создаёт временные Auth-аккаунты сотрудника/посетителя, проверяет доступ и удаляет их в `finally`; нужны серверные Supabase-переменные. Не публикуйте Auth-значения и приватные отчёты. Браузерные сценарии не создают брони и не отправляют Telegram-сообщения.

Lighthouse использует мобильный профиль, симуляцию нагрузки и чистое хранилище посетителя. Сохраняются HTML/JSON и итоговые метрики. Цель Word-плана — performance ≥85; это лабораторное измерение, не гарантия одинаковой скорости на любом устройстве. В облачной среде `QA_HTTPS_BRIDGE=1` пропускает HTTPS браузера через Node fetch с доверенным CA и штатным прокси; проверка TLS сохраняется. Для обычной среды мост не нужен. Подробные результаты — в документе приёмки.

## Деплой

Импортируйте репозиторий в Vercel, задайте серверные переменные и примените миграции Supabase. Корень — корень репозитория, сборка — `npm run build`, preset — Next.js. В текущем проекте merge в `main` запускает production-деплой. После него проверьте RU/EN, `/sitemap.xml`, `/robots.txt`, вход/восстановление пароля и `getWebhookInfo`.

Расширение бота, «Книга месяца» и реальный учёт занятости столов не входят в оставшуюся приёмку исходного Word-плана.
